# Аналитика

Раздел основной программы предназначен для расширяемого набора read-only отчётов. V1 содержит «Сводку по поставщикам».

Источником служит один завершённый `trips.id`. Дата отчёта — `trips.exit_time`; масса нетто вычисляется из `entry_measurements.weight_brutto - exit_measurements.weight_tare` (килограммы) и точно переводится в тонны. Рейсы без завершённого статуса исключаются. Завершённый рейс с отсутствующим измерением может учитываться в количестве, но не добавляет фиктивный нулевой вес.

Production-автомобиль сопоставляется с `supplier_vehicles` существующей функцией нормализации госномера. Поставщик выбирается из `vehicle_supplier_assignments`, период которого включает календарную дату завершения рейса. Поэтому переназначение не меняет старые отчёты. Неактивные поставщики загружаются в фильтр для исторических запросов. Рейсы без сопоставленной административной машины или действующего назначения в V1 не включаются в строки поставщиков.

API:

- `GET /api/analytics/supplier-summary?date_from=YYYY-MM-DD&date_to=YYYY-MM-DD&supplier_id=...`;
- `GET /api/analytics/supplier-summary/export` с теми же фильтрами.

Конечная дата включается полностью через полуоткрытый диапазон до начала следующего дня. По умолчанию UI выбирает текущий календарный месяц. Пагинация не применяется: результат содержит одну агрегированную строку на поставщика.

JSON и XLSX используют один сервис `services/analytics/supplier_summary.py`. XLSX создаётся через `openpyxl`; вес и количество рейсов являются числовыми ячейками. Объём и насыпная плотность остаются пустыми/`NULL`, пока не появится разрешённый канонический production-источник объёма.

Схема БД не менялась. Analytics является read-only. TODO security: после появления общей авторизации к router можно подключить централизованную dependency просмотра аналитики; frontend не считается механизмом защиты.
