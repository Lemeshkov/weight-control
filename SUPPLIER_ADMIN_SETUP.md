# Администрирование поставщиков, машин и заявленных характеристик угля

## CRUD V3: создание, исправление и безопасное удаление

Создание и редактирование теперь являются разными операциями. Создание вызывает `POST` и добавляет строку; редактирование вызывает `PATCH` для выбранного ID и сохраняет идентичность строки и все внешние связи:

- `PATCH /api/admin/suppliers/{id}`;
- `PATCH /api/admin/vehicles/{id}` (только свойства машины; смена поставщика остаётся отдельным историческим событием);
- `PATCH /api/admin/coal-grades/{id}`;
- `PATCH /api/admin/coal-specs/{id}`.

Для спецификаций угля «Редактировать» исправляет текущую активную запись с тем же ID. Историческая или закрытая запись неизменяема и возвращает `409 COAL_SPEC_HISTORICAL_EDIT_FORBIDDEN`. «Новая версия» — отдельная явная операция `POST /api/admin/coal-specs/{id}/replace`: она закрывает прежнюю версию и создаёт новую.

Удаление доступно для всех четырёх справочников после подтверждения. Поставщик и марка удаляются только без ссылок. Машина удаляется только без производственной истории; единственное начальное открытое назначение новой машины удаляется в той же транзакции, а закрытые или множественные назначения блокируют удаление. Удаляется только текущая неисторическая спецификация; закрытая/неактивная версия сохраняется. Конфликты возвращаются как структурированный `409` (`SUPPLIER_IN_USE`, `VEHICLE_IN_USE`, `COAL_GRADE_IN_USE`, `COAL_SPEC_IN_USE`) без SQL-деталей.

Автоматического объединения или удаления дублей нет. Администратор выбирает конкретный ID и может удалить только неиспользуемый дубль; связанная запись сохраняется с объяснением причины. Ключи строк UI основаны на database ID.

Модуль ведёт производственные справочники, но не участвует в текущих расчётах взвешивания, LiDAR или объёма.

```text
Supplier
  ├── Vehicle
  │     └── Supplier Assignment History
  └── Coal Grade / Specification
        ├── Calorific value + explicit unit
        ├── Moisture
        ├── Ash
        └── Fraction constraints

Laboratory Results
  └── remain separate actual measurements
```

Переиспользованы канонические таблицы `suppliers` и `coal_grades`, уже используемые лабораторией и приёмкой угля. Миграция `20260905_01` безопасно расширяет поставщика и добавляет `supplier_vehicles`, `vehicle_supplier_assignments`, `supplier_coal_specs`, `supplier_coal_fraction_specs`. Она не добавляет демонстрационные записи.

Назначение машины поставщику хранится периодами. Переназначение закрывает прежний открытый период и создаёт новый. Изменение заявленной спецификации выполняется созданием новой версии; старая версия закрывается предыдущим днём. Поэтому будущая сессия сможет сохранить конкретные ID назначения и спецификации без зависимости от текущих справочников.

Заявленные значения поставщика не являются лабораторными измерениями. Фактические анализы остаются исключительно в существующем лабораторном модуле и не перезаписываются.

API находится под `/api/admin`: suppliers, vehicles, vehicle supplier-history/reassign, coal-grades, coal-specs и coal-spec replacement/status. Все списки имеют server-side pagination и стабильную сортировку. UI: верхнее меню **Администрирование**, вкладки **Поставщики**, **Машины**, **Марки угля**, **Характеристики угля**.

Физическое удаление поставщика разрешено только при отсутствии ссылок из назначений машин, спецификаций, лабораторных экспериментов и приёмки угля. При наличии ссылок API возвращает контролируемый `409 SUPPLIER_IN_USE`; поставщика следует деактивировать. Аналогично, физическое удаление марки разрешено только для полностью неиспользуемой записи, иначе применяется деактивация.

Единственный источник марок — каноническая таблица `coal_grades`. Вкладка **Марки угля** позволяет создавать, редактировать, активировать, деактивировать и безопасно удалять записи. Созданная марка сразу загружается через `/api/admin/coal-grades` и доступна в форме новой спецификации без перезапуска. Новая спецификация показывает только активные марки; исторические карточки продолжают отображать имя связанной неактивной марки. Runtime frontend не содержит списка марок. Отдельный `seed_coal_acceptance_directories.py` содержит явные начальные данные для ручного seed-процесса и не является runtime-справочником.

В проекте нет реально применяемой middleware-проверки ролей для этих маршрутов. `ADMIN_AUTHORIZATION_AVAILABLE = NO`; перед внешней публикацией API требуется подключить общую авторизацию, когда она появится.
